上传识别

POST {Hub}/me/ocr/recognize
multipart，字段名 images，Bearer 用户 token。护栏：≤20 张、单张 ≤8 MiB、超时 90s。

4

服务端返回结构化成绩

专用模型（曲绘 ArcFace + 标题分类双路）。直接回曲名候选 / 达成率 / DX 分 / 难度 / FC / FS，不是原始文本块。

5

本地曲库补全

拿曲名查 MaimaiMusicDataManager，补曲绘 / 版本 / 流派 / 等级 / 定数。查不到就整体不显示，不硬塞错曲绘。曲绘走网络时提前预热。

→
6

卡片展示 + 玩家修正

六项可改：歌曲（搜库）/ 难度（内联展开，只列该曲真实存在的难度）/ 达成率 / DX 分数（实时上限校验）/ FC / FS。

→
7

上传成绩

两个按钮，各自独立 loading。可直接点，也可以先改再传。

同步到水鱼

端点/player/update_records（批量）
认证Import-Token 头（已有缓存）
歌曲定位曲名 title + 类型，服务端反查
类型值DX / SD
DX 分dxScore

同步到落雪

端点/api/v0/user/maimai/player/scores
认证Authorization: Bearer（落雪 OAuth）
歌曲定位数字 id，需从水鱼 id 取余转换
类型值dx / standard / utage
DX 分dx_score

两条路的差异（写错会静默记到别的曲目上）

  • 歌曲标识方式不同：水鱼传曲名让服务端反查；落雪传数字 id，且两边 id 体系不一致（水鱼 11466 → 落雪 1466，取余 10000）。
  • 宴会场（id ≥ 100000）是个陷阱：落雪这边不能取余（会指向无关曲目），而且它不走 0–4 难度索引 —— 所以落雪那条路直接拒绝同步宴会场谱面并给出明确原因。
  • 静默失败要自己挡：水鱼服务端对「曲名匹配不到」和「难度索引越界」都是 continue 跳过，照样返回 200 成功。所以客户端检查 creates + updates == 0 并报错，否则用户会以为同步成功了。

验证状态 这是当前最要紧的事

  • 已验证 识别链路（1–5 步）：整条走通。flutter analyze 零 error。
  • 已验证 落雪 id 转换：拿两边公开曲目表逐首比对 1332 首，取余后曲名一致 1331 首；6 个单元测试全过。已知例外 1 例（Link(CoF)）。
  • 未验证 两个上传按钮（第 7 步）一次都没真调过，也没构建过 APK。落雪认证到底该用 OAuth 还是个人密钥，只有真调一次才知道。
