## 1. 一句话结构

**9 个单人模式共用一套「游戏骨架」，只有"题面渲染器"和"判定器"不同。**
所以前端的核心不是写 9 个页面，而是写 **1 个骨架 + 9 个模式插件 + 1 个模式注册表**。

```
/rules        纯函数：抽曲池、出题、判定、提示、计分      ← 与 App 口径对齐的地方
/modes        9 个模式插件：{ 题面组件, 判定器, 默认设置 }
/components   骨架与通用件：作答栏、历史表、计时条、设置面板…
```

## 2. 信息架构 / 路由

| 路由 | 页面 | 说明 |
| :--- | :--- | :--- |
| `/` | 首页 | 用户名输入（存 localStorage）+ 9 个模式卡片 + 「多人游戏」入口 + 最近设置 |
| `/play/:mode` | 单人对局 | 骨架页；设置以右侧栏（桌面）/ 底部抽屉（移动）呈现 |
| `/play/:mode?seed=…` | 可复现对局 | **Web 独有**：同一 seed 出同一套题，用于分享"你能全对吗" |
| `/multiplayer` | 多人大厅 | 创建 / 加入 / **「你还在房间 XXXXXX 里，点击返回」**（断线复位） |
| `/room/:code` | 房间 | 等待中与对局中共用一页，按 `room.status` 切换视图；房号可直接分享 |
| `/result` | 结算 | 本局明细 + 一键生成成绩图（canvas → PNG） |

单人对局**不需要服务端**（曲库/别名/音源/曲绘全可跨域直连），所以 `/`、`/play/*` 可以纯静态部署；多人两条路由才需要反代。

## 4. 组件清单

### 4.1 骨架件（所有模式共用）

| 组件 | 职责 | 备注 |
| :--- | :--- | :--- |
| `GameShell` | 顶栏 + 主区 + 侧栏/抽屉 + 吸底作答栏 | 唯一布局来源 |
| `RoundHUD` | 第 x/N 轮、计时条、得分、跳过 | 计时用 `requestAnimationFrame` 驱动，不用 setInterval |
| `SongSearchInput` | 曲名/别名模糊搜索 + 键盘上下选 + 回车提交 | **必须处理中文/日文输入法 composing**（见 §6.1） |
| `GuessHistory` | 本局已答/已猜列表 | 两种样式：列表（曲绘类）/ 属性对照表（信息类） |
| `SettingsPanel` | 版本/流派/定数/轮数/时限 | 默认值与 App 完全一致；存 localStorage |
| `ResultDialog` | 本轮结果（对/错 + 答案曲绘 + 得分） | 自动进入下一轮倒计时 |
| `ShareCardGenerator` | 结算图（canvas → PNG 下载/复制） | Web 版比 App 简单得多 |

### 4.2 题面件（每模式一个，`modes/*/Stage.tsx`）

| 模式 | 题面组件 | 实现要点 |
| :--- | :--- | :--- |
| 曲绘猜歌 | `CoverStage` | 直接 `<img>`，右下角显示曲绘 ID（可选提示） |
| 模糊曲绘 | `BlurStage` | `filter: blur(Npx)`，N 随回合/提示递减 |
| 曲绘快闪 | `FlashStage` | 闪现 `flashDurationMs` 后 `opacity: 0`，可回看次数有限 |
| 曲绘拼图 | `TileStage` | `background-position` 分块揭示；`tileCount`/`tileRevealIntervalMs` 与 App 同默认值 |
| 歌曲片段 | `AudioStage` | `<audio>` + 播放窗口进度条 + 剩余秒数；随机起点 |
| 信息猜歌 | `InfoStage` | 属性表 + 绿/黄/灰 + ↑↓ |
| 别名猜歌 | `AliasStage` | 展示别名（多个用「、」连接），答案反向匹配 |
| 开字母 | `LettersStage` | □ 掩码 + 已开字母高亮 + 字母键盘 + 多首目标的进度点 |
| 谱面片段 | `ChartStage` | v2：canvas 渲染 + 音频时间轴同步 |

### 4.3 多人件

`RoomCodeInput`（6 位数字，自动跳格）、`PlayerList`（含掉线置灰）、`ReadyButton`、`HostControls`、`GuessFeed`、`ConnectionBanner`（重连中/已复位）。

## 5. 状态与数据流

```
                    ┌───────────────────────────────┐
  构建期快照 JSON → │ SongRepo / AliasRepo（内存索引）│ ← 需要时后台增量更新
                    └──────────────┬────────────────┘
                                   │ 纯查询：pool(filters) / byId / search(q)
                    ┌──────────────▼────────────────┐
                    │ rules/*（纯函数，可单测）        │
                    │ pickSong → judge → hints → score│
                    └──────────────┬────────────────┘
                                   │
              useGameSession(mode, settings, seed)  ← reducer + 状态机
                                   │
        GameShell / Stage / GuessBar / History（只读 state + 派发 intent）

  多人：WsClient（事件流）→ useRoomStore（zustand）→ 房间 UI
```

- **单局状态机**：`idle → preparing → playing(round) → judged → (next round | finished)`；跳轮/超时都走同一批 action，便于录制回放。
- **seed 化**：`useGameSession` 接受 seed，抽曲 rng 由 seed 派生 → 分享链接可复现同一套题（也方便 e2e 测试）。
- **服务端状态**：曲库/别名是只读快照，用 `useSyncExternalStore` 或 TanStack Query 缓存；不进全局状态库。
- **不做全局状态库**（除多人房间 store）。单人只靠 hook + context，避免过度设计。

## 6. 交互规范

### 6.1 输入（Web 特有坑，必须写进实现约定）

- **输入法 composing**：`Enter` 提交前要判 `e.nativeEvent.isComposing`，否则中文/日文选词会被当成提交；
- 输入框进轮次自动聚焦（移动端会唤起输入法，需可关闭）；
- 上下键在候选列表里移动、`Enter` 选中、`Esc` 清空；`Tab` 在候选与提交键间切换；
- 全角/半角、大小写、去空格后比较；连续两次相同答案提示"已经猜过了"。

### 6.2 判定的三层匹配（与 App 一致）

`精确匹配` → `别名匹配`（AliasRepo）→ `规范化匹配`（去空格/大小写/全半角/罗马字转写）。
命中哪一层要在 UI 上回显（"✓ 别名命中"），否则玩家会怀疑判定。

### 6.3 键盘与无鼠标可玩

`1–9` 切模式（首页）、`Space` 暂停/继续倒计时、`R` 重开本局、`S` 跳过本轮、`Ctrl/Cmd+Enter` 直接提交。桌面是 Web 版主场景，键盘可达性是硬要求。

### 6.4 断线（多人）

`ConnectionBanner` 三态：`已连接` / `重连中…（不影响座位）` / `已复位到房间`。刷新页面时用 localStorage 里的 `playerId` + 上次房间号自动复位（服务端宽限期 120s 内）。

## 7. 视觉

- **深色为默认**：沿用 App 的主题 token（深色底 `#121220`、卡片 `AppColors.cardBackground`、主题色 primary 系），必要时提供浅色；
- **桌面更"疏"**：App 是手机布局（字号按 `屏宽 × 0.0x` 计算），Web 用固定排版尺度（正文 14/16、标题 20/24/32），不要跟着窗口宽等比缩放；
- **曲绘卡片风**：沿用 App B50 卡片的观感（圆角 8、2px 描边、上半曲绘下半白底信息条），保证 IP 一致性；
- **状态色**：绿=完全一致、黄=接近、灰=差得远（信息模式）；成功/失败/掉线各一套语义色；
- **断点**：`≥1024` 三栏 / `768–1023` 两栏 / `<768` 单栏 + 吸底作答；
- **动效克制**：仅"回合切换""判定反馈""拼图揭示"三处做动画，避免手机上掉帧。

## 8. 目录结构（概设）

```
web-guess/
├─ src/
│  ├─ app/            # 入口、路由、主题 token、i18n（预留）
│  ├─ data/           # songRepo / aliasRepo / coverResolver / audioResolver / 快照加载与更新
│  ├─ rules/          # pool.ts / pick.ts / judge.ts / hints.ts / score.ts / letters.ts / translit.ts
│  ├─ modes/          # registry.ts + info|cover|blur|flash|tile|audio|alia|letters|chart/
│  ├─ components/     # GameShell / RoundHUD / SongSearchInput / GuessHistory / SettingsPanel …
│  ├─ multiplayer/    # wsClient.ts / roomStore.ts / 房间组件
│  ├─ pages/          # Home / Play / Lobby / Room / Result
│  └─ styles/
├─ public/
│  ├─ covers/         # 构建期从 ../../assets/cover 拷贝（不在 git 里重复存）
│  └─ data/           # 曲库/别名/曲绘索引快照（构建期生成）
├─ tests/
│  ├─ unit/           # rules 的单测
│  ├─ fixtures/       # 从 App 导出的口径用例（契约测试）
│  └─ e2e/            # Playwright：seed 复现、键盘作答、多人两人同房
└─ package.json · vite.config.ts · tsconfig.json · .gitignore
```

**加一个模式 = 加一个 `modes/<id>/` 目录 + 在 `registry.ts` 注册一行**，骨架与设置面板不用动。

## 9. 与 App 的差异（Web 独有的取舍）

| 点 | App | Web 版 |
| :--- | :--- | :--- |
| 布局 | 手机竖屏，字号随屏宽缩放 | 桌面优先、响应式；键盘可达 |
| 分享 | 导出图片到相册 | **URL 可分享**（房间号链接、`?seed=` 挑战链接）+ 一键存图 |
| 进度保存 | SharedPreferences | localStorage + 刷新即恢复本局 |
| 离线 | 本地曲绘/音频缓存 | Service Worker 可选缓存最近 N 首音频 |
| 谱面片段 | `simai_flutter` 渲染 | v2 自写 canvas 渲染（或先不做） |
| 多人 | 原生 WS 客户端 | 同一协议、同一服务端（换 wss 入口） |

## 10. 待你确认（会影响后续实现顺序）

1. **首页九宫格 vs 直接进模式**：保留首页（可挂多人入口与最近设置）还是打开就进上次的模式？

4. **浅色主题**：只做深色，还是一开始就把 token 做成双主题？
