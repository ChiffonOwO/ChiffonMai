# 三账号状态审计与维护说明

本次范围是水鱼、落雪、AWMC NET 的本地账号状态，以及调用这些状态的刷新、同步后自动刷新、登出、历史和派生缓存。未连接设备，也没有向真实账号发起查询、成绩上传或排行榜修改。

## 修复的问题

| 触发条件 | 原有影响 | 处理 |
| --- | --- | --- |
| 首次刷新没有缓存的另一个源 | 仍拿旧源活动槽写入，历史归属错误 | 无缓存也建立目标活动槽；原活动槽先存档 |
| 普通刷新、自动刷新、切换、清理同时发生 | 多个任务交错覆盖同一活动槽 | `AccountSwitchService.runRefresh` 覆盖整个刷新周期；切换/清理使用同一个锁 |
| 第二次刷新被拒绝 | 若调用端统一回滚，可能回滚仍在运行的第一个任务 | 锁的获取、提交、回滚由协调器同一个调用持有 |
| 网络失败、目标存档写到一半、进程中断 | 新旧账号字段混合，或一份存档只更新一半 | 持久化恢复标记保存原账号和目标存档旧版本；恢复前清槽 |
| 首页/系统页同步完成 | 先写数据源标记，再刷新活动槽 | 删除独立的数据源回调；自动刷新走与手动刷新相同的事务 |
| 当前是落雪/AWMC 时登出水鱼 | 删除当前账号的成绩、QQ、Rating | 水鱼凭据清理和账号清理在同一个事务中；非活动账号只清其自身 |
| 系统页加载资料、同步或 OCR 使用 QQ | 把当前平台 QQ 与水鱼绑定 QQ 混用 | 活动资料只读活动槽；水鱼操作只读水鱼可信绑定 QQ |
| 同一平台更换 QQ/friendCode | 继续使用前一人的历史、评论身份和派生数据 | 历史使用平台 + ID；提交新身份时清旧活动槽和旧游玩次数 |
| 好友对比 | 临时写入好友成绩，恢复时可能覆盖新账号/新成绩 | 查询改为只返回数据，不改活动槽、不采集历史 |
| 落雪刷新 | 重复拉取成绩、失败时保存零值、未采集谱面历史 | 复用一次请求的成绩；缺失数据/转换失败中断并回滚；通过公共提交入口采集 |
| 对话框选择另一个平台并改排行榜开关 | 立即修改原活动账号设置 | 选择时读目标设置，成功刷新时在目标上下文内保存 |
| 切换后查看牌子进度、每日推荐、Best50 快照 | 使用另一账号的内存/全局缓存 | 内存失效与过期任务检查；每日推荐和快照按平台 + ID 分键 |
| 历史页读取期间切换账号 | 旧请求覆盖新页面、曲线和摘要来自不同源 | 一次读取固定命名空间，订阅账号变更并丢弃迟到结果 |
| Rating 和谱面历史同时落盘 | 同一个 `.tmp` 文件被同时写入 | 按历史文件串行写盘 |

## 今后的入口约束

1. 当前活动槽继续使用 `user_play_data`、`cachedQQ`、`userNickname`、`best50TotalRA` 等键，现有读取方无需全部重写。三个源各自的存档由 `AccountStore` 管理。
2. 任何会修改活动槽的成绩刷新必须由 `AccountSwitchService.runRefresh(source, body)` 包住。普通刷新、高级刷新、首页和系统页的水鱼自动刷新都通过源对应的公开刷新函数进入这一事务。禁止自己先写 `last_data_source`。
3. `fetchUserPlayData` 现在是只读查询。自己成绩由事务内先 `bindIdentity`，再 `storeFetchedData` 提交。该入口检查异步作用域的归属，不能借另一个正在运行的刷新取得写入权限。
4. `CurrentDataSourceNotifier.set` 仅由协调器维护。水鱼登录/同步拿到的绑定 QQ 属于水鱼凭据，不等同于活动槽 QQ。
5. 登出通过 `onAccountLoggedOut`，凭据删除放到 `clearCredentials` 回调里。水鱼现有入口委托 `UserProfileNotifier.clearShuiyuAccountCache`；不要在外面先删共享键。
6. 与具体用户有关的持久化结果使用 `AccountStore.accountKey`，异步计算开始时捕获。需要写活动槽的长任务应检查账号 revision，过期结果不得落盘。
7. `account_rotation_pending` 是本机恢复日志，不进用户备份。归档写入失败必须往上传播，不能日志一打就继续清活动槽。

## 兼容性和边界

- 升级前已知账号的按源历史会复制到该账号的独立文件，原文件保留。迁移归属先持久化，重试不能把旧历史认领给后来换入的账号。原先已经混写的历史点缺少账号身份，无法自动判断每个点实际属于谁。
- 旧 Best50 快照绑定到升级时活动账号并保留旧键。旧的每日推荐缓存可以重新生成。好友对比新历史按水鱼 QQ 分键，原共享历史不删除、不猜测归属。
- 这是本地状态事务。远端排行榜更新/删除已经执行的部分无法由本地回滚撤销；失败会明确向调用方报错，之后重试。
- 三个源仍各有一个可切换的缓存槽，不变成任意数量账号的账号管理器。历史支持同平台换人后分别保留，再切回同一个 ID 时可读取原历史。
- 本次修改包括现有被 Git 忽略的 `lib/service/AWMC/AwmcPlayCountStore.dart`（清理内存缓存、固定请求来源及拒绝清理后迟到的结果）。发布时应核对该文件是否被纳入实际交付；不要直接把整个含凭据的目录取消忽略。

## 验证

行为测试见 `test/account_isolation_test.dart`、`test/chart_history_wiring_test.dart`、`test/rating_history_page_test.dart`。覆盖本地事务、崩溃恢复、并发拒绝、旧历史迁移、跨平台/同平台身份隔离，以及模拟 HTTP 查询不污染活动槽。另运行已有历史、游玩次数、数据源、同步对话框、首页和 PC50 回归测试。

按照项目约定运行 `flutter analyze --no-pub`，要求零 error；仓库原有 warning/info 不等于本次检查零问题。没有修改 Android 文件，不构建 APK。真机行为、真实平台登录/同步、Kotlin/打包未验证。

本次最终结果：上述相关回归测试共 147 项通过；全仓库 analyze 为 0 error，仍报告 820 条 warning/info（所以命令退出码不是 0）。本次涉及的差异通过 `git diff --check` 检查。
